# 小红书招募测试用户策略

记录于 2026-08-13 的一轮讨论结果。**2026-09-10 起已经正式开始执行**，见文末「2026-09-10 更新」——下面的原始讨论内容仍是背景参考，但节奏和账号人设已经调整，以更新章节为准。

## 2026-09-10 更新：正式开始执行，账号人设+发布节奏都有调整

- **发布节奏从"2-3篇"改成"批次制"**：找 xiaohongshu-specialist agent 咨询后，采纳建议——零粉丝新号不适合提前锁死全部顺序，改成**3-4篇一批，批内间隔3-5天，一批发完看数据再决定要不要/怎么扩到下一批**。批次1共4篇（见下）。
- **账号人设从"匿名品牌号"改成"用户本人/开发者第一人称"**：参考了用户提供的大马独立开发者博主"瞌睡的Nelson"（rednote，实际是 `docs/竞品分析-money2time.md` 里分析过的 Money2Time 开发者）——他的高赞帖全是真实、不加修饰的实拍图/App真实截图，不是精修文字卡片，这直接决定了后续配图方向。人设细节：不匿名，第一人称真实语气；**不露脸**，用卡通/非人脸头像；定位不是"程序员"而是**"AI小白/靠vibe coding把想法做出来"**（用户本人澄清：不是专业程序员）。
- **批次1构成（因人设调整，比原计划多一篇）**：① 开发者自我介绍/起源故事 → ② 痛点吐槽型 → ③ 身份认同型（大马华人视角，不限定家人或朋友，特意从①里挪出来放这篇） → ④ 干货攻略型。①已于 2026-09-10 发布：《不会写代码的我，靠 Vibe Coding 做了个App》，配图是本地测试模式的真实App截图（账本页+行程页），hashtag 用平台话题自动补全确认成真实话题（非纯文字）。
- **私信策略微调**：担心账号主动私信陌生人触发风控，改成"评论区留言 → 账号在评论区公开回复引导对方来私信"，账号本身绝不主动发起私信。
- **发现一个小红书平台本身的bug，很重要**：图文笔记的草稿，图片在编辑器里当场看是好的，但"暂存离开→重新打开草稿"之后图片必定变空白（已连续复现3次，上传到图床的原始请求其实是成功的，但保存草稿时会调一个内部代理接口，抓到过一次503）。**结论：草稿不要放着不管，建完尽量当场审核/发布，不要跨会话回来看。** 草稿箱本身也是纯本地浏览器存储，不同浏览器/设备/手机App之间不同步。
- **决定不做全自动定时建草稿**：图片持久化bug + 每篇文案都需要用户提供真实细节（不是套模板），所以只设了一个**定时提醒**（`xhs-post-checkin` 定时任务，会在发布后第4天左右主动来问方向），实际写文案/建草稿还是要interactive进行。
- 剩余待做：②痛点吐槽、③身份认同、④干货攻略，均未开始写文案。

## 2026-09-14 更新：②痛点吐槽正式发布，批次1过半

- **②痛点吐槽型《旅行回来最尴尬的，是要跟朋友讨钱》已发布**。最终配图是2张：图1是AI生成的"手拿手机看聊天记录、咖啡馆背景"实拍风格照（ChatGPT生成，效果很好——连JPY/MYR混合货币这种细节都编对了，"Amy/Ben/Chris"这种国际化朋友群也呼应了不限定家庭的原则），图2是App"结算"页真实截图（`账目→结算`标签页，展示"阿灰→爸爸 RM1,817.28"这类结算建议，直接对应正文"App自己算出谁该收谁该付"这句）——**这次用户主动要求加了产品截图**，推翻了我之前"这篇该保持纯生活场景图、不加截图避免软广感"的建议，用户判断优先。
- **文案迭代中两次被用户抓到真实问题，都是过渡/逻辑硬伤，不是文风偏好**：①CTA"评论区找我"和前面痛点吐槽衔接生硬，加了"旅记还在早期阶段、还没大规模开放"这句桥接句才通顺；②"这也是我做这个App想解决的一个点"这句被指出"说着分账痛苦突然带入App"太跳，改成承接上一句原词的"这种别扭，也是我做旅记最想解决的一个点"，用重复关键词做钩子，读起来才是同一个思路在往下走而不是话题切换。**以后写"痛点→带出产品"这类过渡，默认要用承接句里的原词起头，不要另起炉灶。**
- **App截图分辨率教训**：Playwright截图默认`deviceScaleFactor`是1，产出的是430×932这种CSS像素级别的图，实际发到帖子里放大看是糊的（用户明确反馈"很模糊"）。**以后凡是要放进真实帖子的App截图，必须设置`deviceScaleFactor: 3`**（对应iPhone Retina密度），产出约1290×2796这种真实分辨率的图，缩略图阶段可能因为渲染太小看着还是有点糊、不用慌，最终发布出来是清晰的。
- **再次确认"存草稿会丢图"这个平台bug的边界**：这次流程里，图片在"重新打开草稿""上传后又被要求重传一次"这几个环节都反复丢失过、需要重新上传定位到具体哪个图片slot再补传——反复出现，不是偶发。当前唯一稳定的应对方式就是：**改完就现场核对好、直接发布，不要中途保存离开又回来看**。
- **正文里出现过一次诡异的文字篡改**："这种别扭，也是我做旅记最"这句里的"旅记"，在没有任何编辑操作的情况下变成了"App"——原因未知（怀疑还是和图片那个内部代理服务不稳定有关，可能牵连了文本自动保存/恢复的某个环节），已手动改回。**发布前建议整体通读一遍正文，不要只信任"看起来没变"。**
- 剩余待做：③身份认同（大马华人视角）、④干货攻略（可能用插画标题卡格式，待定）。
- **②发布后被小红书判定违规、笔记被限制**（处置结果"该篇笔记已不可被他人查看"，平台建议措辞指向"曝光隐私/人肉搜索"类审核）。根因判断：第1张AI生成的聊天记录图里带了一个看起来真实的手机号（"+60 12-345 6789"），即使是虚构内容，视觉上跟"真实泄露的私聊截图"无法区分，触发了隐私类审核。**教训：以后任何"聊天记录/私信截图"风格的AI配图，绝对不能出现手机号、真实姓名全名、账号ID这类看起来像真人身份信息的内容**，哪怓是虚构的也不行。修复方式：把第1张图换成插画标题卡（跟④篇同一套模板，纯文字+图形，零隐私风险），用"修改笔记"流程重新提交审核，图2的结算页截图保留不变。**已于2026-09-14由用户确认后自行点击发布重新提交，结果待观察。**

## 背景与目标

- 现状：「旅记」目前只有自己家人 + 少数手动邀请的团队在用，还没做过任何公开招募。
- 需求：最缺真实测试用户，想通过自媒体（小红书）招揽。
- 成功标准：**少而精**——5个左右愿意认真用完一趟旅行并给反馈的人，不是追求曝光量或注册数。

## 冷启动现实评估（关键）

零粉丝新号 + 只发一篇帖子，大概率**达不到**5个精准用户这个目标——不是执行细节问题，是曝光结构性不够（新号权重低，单篇曝光通常只有几十到几百，真正落进"马来西亚华人+旅行+多人记账痛点"这个窄交集的人可能只有个位数）。因此调整为2-3篇，且需要认知到：

- 小红书对新号的推荐机制是分层流量池——早期数据（完播/停留、点赞/评论/收藏/分享）不达标，笔记很难进入更大曝光层，这是结构性的,不是内容写得好就能绕过。
- **收藏率/搜索沉淀**可能比赌算法推荐更现实——笔记标题/正文包含目标用户真的会搜的词（如"结伴旅行记账""家庭旅行记账""大马旅游记账"），有助于笔记长期留在搜索结果里被动获客。
- 纯产品宣传类内容容易被判定软广而限流，痛点/故事切入通常比直接推广表现更好。
- 站外私域导流（大马华人旅游群/FB群，人工制造前几十个互动）对触发早期流量池判定有实际帮助,是零粉丝账号少有的可控杠杆。
- 长期看，小红书笔记更适合定位成"长尾搜索入口+信任背书"，短期5人目标真正的来源可能还是私域（朋友介绍、已有群组直接私信匹配的人）。

## 内容角度（策略概念，还没写文案）

计划测试的角度组合：**A + C，视数据决定是否加发 D**

- **A. 痛点吐槽型**（先发，作为账号"温度计"）：具体窘境式共鸣（如"一群人出国对账对到吵架"，不限定是家人还是朋友），App结尾轻带出。评论率通常高，但共鸣要具体不能泛。
- **C. 身份认同型**（必测）：直接锁定"大马华人"视角，本地化场景切入，不预设旅伴一定是家人。触达面窄但精准度最高，是唯一直接验证"零粉丝单篇能不能精准打到目标人群"的角度。
- **D. 对比/Before-After型**（可选，视A/C数据决定）：以前用Excel/群里报账 vs 现在的对比。点击率钩子强，但偏产品展示，软广风险相对高。
- B（干货/攻略型）不单独占名额,收藏价值可以自然融入A或C的文案结尾。

## 发布节奏

- 顺序：A → C → （视数据）D
- 间隔：每篇约一周，让上一篇数据成熟到可比较的程度
- 固定发布时段：晚8-10点/周末，减少变量方便横向比较三篇表现
- 每篇发完先看数据（曝光、精准画像的人是否留言）,再决定下一篇是否按计划发或调整角度

- 私信收到邮箱后，实际走邀请流程的时间线安排
