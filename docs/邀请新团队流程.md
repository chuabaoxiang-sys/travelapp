# 邀请新团队使用旅记 APP

给陌生团队（不是自己家人）开通访问权限的标准流程。每个团队互相看不到对方数据，也不知道对方存在。

## 2026-08-16更新：加入已有团队现在不用再找我了

如果是"邀请人加入某个已经存在的团队"（比如邀请家人朋友加入自己这个团队），团队里任何一个已登录成员现在都能自己搞定：顶部身份切换 → "邀请新成员加入团队"，把里面的邀请码发给对方，对方在登录页用"有邀请码？点这里输入"自己加入即可，不用再走下面这套人工SQL流程。

下面这套人工流程现在只在**"陌生人要开一个全新的团队"**（不是加入你已有的团队）这种情况下才需要。

## 2026-08-31更新：自助创建全新团队的代码已经做好，但开关是关的

数据库里已经有一个`self_serve_signup_enabled()`开关函数，默认`false`。开关打开后，任何邮箱登录都会被允许（`is_invited_email`不再要求邮箱必须已经在某个`household_member`里），登录后如果发现自己不属于任何团队，App会给一个"创建我的团队"的入口（调用`create_household` RPC），全程不需要开发者手动跑SQL。

**这个开关现在还是关着的**——开关打开后网站等于对任何人开放注册，还需要先做好落地页（现在的登录/注册页直接暴露给陌生访客会显得很粗糙，这个是待办，跟这次改动没有依赖关系）。什么时候打开是以后单独一个决定（可能跟小红书招募一起），不是这份文档更新时就定下来的。

**开关打开的方法**（到时候直接跑，不需要新迁移文件）：
```sql
create or replace function self_serve_signup_enabled()
returns boolean language sql stable set search_path = public
as $$ select true $$;
```
关闭同理，把`true`改回`false`。

**在开关打开之前，下面这套人工建团队流程依然是"开一个全新团队"唯一的路径。**

## 新建团队：你只需要做两件事

### 1. 把下面这段发给我（Claude），填好空格

```
邀请新团队
团队名：____________
邮箱：____________（一个团队可以填多个，用逗号分隔）
类型：新建团队
```

我收到后会：
- 生成对应的SQL
- 告诉你去哪个Supabase项目、贴到哪里跑
- 生成第2步要发给对方的消息，把邮箱帮你填好

### 2. 把生成好的消息发给受邀人（见下方模板）

## 补充材料

**`docs/旅记加入指引.html`** — 完整的5步图文加入指引（每步配界面示意图），独立HTML文件，双击就能打开。**注意：手机上不好用**，.html 附件在 iPhone 上通常打不开或显示成源代码；发给手机用户请用同一份内容发布成的 Artifact 链接（发之前要先在页面分享菜单里开启分享，默认私密）。

**`docs/旅记-APP介绍.pptx`** — 5页简单介绍PPT（核心功能亮点 + 使用流程），可以一起附上，帮受邀人提前了解这是个什么工具。内容是通用的，不用每次邀请都重新生成。

## 两个装桌面的坑（都不是APP的bug，是平台限制）

- **iPhone 只有 Safari 能装成真正的APP**，Chrome/Firefox/Edge 都不行（就算菜单里有类似选项也只是加个普通书签）。APP 现在会识别出来并提示换 Safari。
- **在微信/WhatsApp 内置浏览器里打开也一样装不了**。让 iPhone 用户长按网址复制，自己开 Safari 粘贴。
- 安卓没有这些问题，APP 会自己弹安装提示。

## 发给受邀人的消息模板

> 你好！邀请你来试用「旅记」——一个记录旅行行程+账目的小工具。
>
> 打开这个网址：`<APP网址>`
>
> 会看到"先登录一下"的界面，**输入你自己的邮箱**（就是 `<邀请邮箱>`），点"发送验证码"，然后去这个邮箱找一封带**6位数字**的邮件（如果没看到，查一下垃圾邮件夹），把6个数字填进格子里就能登录，填满会自动验证，不用设密码。
>
> 登录后选一个你的名字（第一次用的话可以自己新建），就能开始用了。有问题随时找我。

## 我（Claude）收到邀请请求后要做的事

1. 确认目标环境是**生产 Supabase 项目**（不是测试项目）
2. 给出新建团队的SQL：

   ```sql
   with h as (
     insert into household (name) values ('<团队名>') returning id
   )
   insert into household_member (household_id, email)
   select id, '<邮箱1>' from h
   union all
   select id, '<邮箱2>' from h; -- 如果有多个邮箱，按需增减这几行
   ```

   （如果是"加入已有团队"，改用APP里的邀请码自助加入，见上方2026-08-16更新，不需要这一步）

3. 请用户去生产项目 SQL Editor 跑，确认无误后
4. 把上面的"发给受邀人的消息模板"填好邮箱、APP网址（当前是 `https://travelapp-kappa-wheat.vercel.app`），交给用户去发
5. 不需要额外验证隔离效果——RLS机制已经过团队A/B真实验证，新团队照同样机制自动生效，不用每次重新测试
